## Two consequences for anything that moves B

**B depends on a sibling directory.** Its `index.html` loads
`../_ds/needt-design-system-main-25d3c8e5-a812-464d-881f-e887b9adef4b/styles.css`
and the matching `_ds_bundle.js`. That directory exists under
`needt-app-design/`. Moving `needt-app/` without `_ds/` gives a blank page with no
error. A used `../../styles.css` instead, resolving inside `Needt Design System/`.

**The screens share one global scope through `TodayScreen.jsx`.** It declares
`PageHeader`, `WEEK`, `DAY`, `PLACED`, `WeekStrip` and `Legend`, and
`CalendarScreen.jsx` uses all of them without importing anything. Load order in
`index.html` is therefore load-bearing: `TodayScreen.jsx` must stay ahead of
`TasksScreen.jsx` and `CalendarScreen.jsx`. No duplicate top-level declaration
exists in B today, so the four-way collision recorded in the handoff is not
currently live in this copy.

## What is genuinely missing from both copies

Neither copy contains `CalendarGrid.jsx`, `ExposureWordmark.jsx`,
`exposure-wordmark.css` or `calendar-cases.html`. The calendar rework of
2026-09-06 and the wordmark exist only inside Claude Design, as §6 recorded.
Deleting A does not put them at risk, because A never had them either.

## Added after DesignSync was connected, same day

Authorization now works. Five design-system projects exist under the account,
and the source of the kit is **Needt Design System Main**,
`25d3c8e5-a812-464d-881f-e887b9adef4b`. That id is the one already baked into
`needt-app-design/_ds/needt-design-system-main-25d3c8e5-a812-464d-881f-e887b9adef4b/`.

Two findings change what "sync" should mean here.

**Local copy B is ahead of the remote project, not behind it.** Fetching
`ui_kits/needt-app/CalendarScreen.jsx` from the project returns the modern
version that imports `DayTimeline` and `FreeTime`, so the remote is already
ahead of local copy A. But it is still behind local copy B: the remote hardcodes
`2 unplaced` as a literal and takes no `tasks` prop, while B accepts `tasks`,
computes `unplaced` from it, and sets `variant="outline"` on the Today button.
The ordering is A, then remote, then B.

Pulling the project down wholesale would therefore destroy local work. Any sync
has to run file by file, in whichever direction each file turns out to need.

**The 2026-09-06 work is in none of the five projects.** The file list for the
main project contains no `CalendarGrid.jsx`, no `ExposureWordmark.jsx`, no
`exposure-wordmark.css` and no `calendar-cases.html`. Every one of the five
projects was last updated on or before 2026-09-01, so none of them can hold work
done on 09-05 or 09-06. Those artifacts live in a Claude Design conversation that
was never saved into a design-system project, and DesignSync cannot reach a
conversation. They have to be exported by hand.

## Action taken, 2026-09-11

The stale copy was retired rather than deleted. It now sits at
`_superseded/2026-09-11-stale-ui-kit/needt-app/`, and `Needt Design System/`
no longer has a `ui_kits/` directory at all. `needt-app-design/needt-app/` is the
only live copy of the app kit in the tree.

Retiring rather than deleting matters because `Needt Design System/` is untracked,
so a delete would not have been recoverable from git. The remote design-system
project also still holds its own copy of that kit, which is a second way back.
